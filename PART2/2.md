1. The Progressive Tax Nightmare
Ask the user for their annual income. Calculate their tax based on these brackets:

     0 to $10,000: 0% tax
     $10,001 to $50,000: 10% tax (only on the amount over $10,000)
     $50,001 to $100,000: 20% tax (on the amount over $50,000) PLUS the tax from the previous brackets
     Over $100,000: 30% tax (on the amount over $100,000) PLUS the tax from all previous brackets
    Print the exact tax amount as a float. 
    Brain tease: You cannot just multiply the whole income by the percentage. You must use if/elif and mathematically isolate the portions of the income that fall into each bracket.

2. The 24-Hour Time Delta
Ask the user for a start time and an end time in 24-hour format (e.g., 1345 for 1:45 PM). Assume the end time is always strictly the same day or the next day.

     Calculate the total difference in minutes.
     If the end time is numerically smaller than the start time, it means the end time is on the next day (e.g., start 2300, end 0100).
     Print the difference in this exact format: "X hours and Y minutes"
     Brain tease: How do you mathematically handle the "next day" rollover using modulo or addition, and then extract the hours and minutes from that total?

3. The 3-Switch Logic Door
Ask the user for the state of three switches (A, B, C) as strings ('True' or 'False').

     The heavy steel door opens ONLY IF: (A is True AND B is False) OR (B is True AND C is False).
     HOWEVER, if A, B, and C are ALL False, the door locks permanently. Print "LOCKED".
     If the door opens, print "OPEN". If it doesn't open and isn't locked, print "CLOSED".
     Brain tease: You cannot use the strings 'True' or 'False' directly in Boolean logic. How do you evaluate them? The order of your if/elif/else conditions is the only way to solve this without logical contradictions.

4. The Floating-Point Validator
Ask the user for their height in meters and weight in kilograms.

     Convert the inputs to floats.
     Calculate the BMI: weight / (height ** 2).
     If the height is greater than 2.5 or weight is greater than 500, print "Invalid human dimensions." and do not calculate the BMI.
     If the dimensions are valid, check the BMI:
         If BMI is exactly 22.0, print "Perfect BMI."
         If BMI < 18.5, print "Underweight."
         If 18.5 <= BMI <= 24.9, print "Normal."
         If 25.0 <= BMI <= 29.9, print "Overweight."
         If BMI >= 30.0, print "Obese."
     Brain tease: Comparing floats with == is dangerous. How do you guarantee 22.0 triggers the "Perfect" condition without breaking the "Normal" condition? You must order your conditions flawlessly.
